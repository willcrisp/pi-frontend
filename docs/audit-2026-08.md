# Maintainability pass — August 2026

Follow-up to `docs/audit-2026-07.md`, which was a feature/UX audit. This one is
about the code: is it still composable, and what has accumulated.

Method: read the tree; checked the July findings against current source; scripted
the import graph, the export surface, the storage/fetch discipline and the style
partial↔import mapping. `npm run build` is clean (122 modules, 2.2s). The
Playwright suite was **not** run, per `AGENTS.md`.

---

## Verdict

**The architecture held.** Every structural claim in `CLAUDE.md` still checks out
against the source, which is not the usual outcome three months and a large
feature drop later. The July audit's ten findings are essentially all fixed, and
fixed at the right layer rather than patched at the call site.

What has accumulated is narrower than last time and mostly of one kind: **a
shared abstraction was introduced but only half-adopted, and the un-adopted half
is now being compensated for elsewhere.** That is the finding worth acting on.
Everything else is hygiene.

## A. Escape is owned three different ways, and they don't know about each other

The one finding with a user-visible bug behind it.

`useDialogEscape` was introduced to be *the* close contract, with a `stack` so
that only the topmost dialog reacts. Adoption stopped halfway:

| Mechanism | Surfaces |
|---|---|
| `useDialogEscape` stack | ConfirmDialog, HandoverDialog, McpDialog, ProvidersDialog, SavedPermissionsDialog, SubagentsDialog, UsageDialog |
| Hand-rolled `window` keydown | CommandPalette, ShortcutsDialog, ImageAnnotator, QuestionDialog, PermissionDialog |
| DOM sniffing | `Composer.vue#ESCAPE_OWNERS` — nine CSS selectors |

Three consequences, in increasing order of severity:

1. **The `enabled` option is dead.** No caller passes it. Its header comment
   claimed `PermissionDialog` uses it to avoid accidental dismissal —
   `PermissionDialog` does not import the composable at all. (Comment corrected
   in this pass.)

2. **`ESCAPE_OWNERS` is the coupling the composable was meant to delete.**
   Escape-to-interrupt has to guess whether another surface owns the key by
   querying the DOM for nine hardcoded selectors. Adding a dialog now means
   remembering to edit a selector list in an unrelated component — and the
   existing comment already records that getting a selector subtly wrong
   (`.select-menu` vs `.select-panel`) silently disabled the shortcut entirely.
   That is a trap that will be stepped in again.

3. **Escape can act on two surfaces at once.** None of the five hand-rolled
   handlers checks `e.defaultPrevented`. With a dialog open and a
   `permission.v2.asked` arriving on top of it, one Escape closes the dialog
   *and* rejects the permission. And because plain `window` listeners fire in
   registration — i.e. mount — order, the surface opened **first** wins, which is
   backwards for a modal stack.

**Fixed.** `useDialogEscape` now owns **one** `window` listener for every
participant, so two surfaces can no longer act on one press — there is only one
handler to do the acting. Adoption went from 7 components to 20: the five
hold-outs plus the popovers, `SelectMenu`, `FindBar`, `FilePreview`,
`ModelFilterPopover` and the narrow-layout sidebar drawer.

Two things the rewrite needed beyond the original design:

- **`open` instead of `enabled`.** Most of these surfaces are mounted for the
  life of the app and toggle a `v-if`'d panel (the palette has to keep listening
  for Ctrl+K while closed), so mount order says nothing about which is on top.
  Passing `open` raises the entry when it becomes true, making the stack ordered
  by *when each surface opened*. Dialogs mounted only while open keep their mount
  position, which is already right.
- **Callback close actions**, so `PermissionDialog` denies and `QuestionDialog`
  skips rather than merely closing. `PermissionDialog` takes the key handler but
  not `onBackdrop` — a gating decision shouldn't be made by a click that misses
  the panel.

`ESCAPE_OWNERS` is gone; `Composer.vue` asks `escapeIsOwned()`. Two surfaces that
were in that list only to *suppress* the interrupt — `ModelFilterPopover` and the
sidebar drawer — had no Escape handling of their own, so the shortcuts dialog's
promise was false for both. They honour it now.

`test/escape.spec.js` covers the stacking order, the interrupt's priority, and
the permission-over-dialog case specifically, and says which past bug each pins.
Not run: per `AGENTS.md` the suite waits for an explicit request.

## B. `ProvidersDialog.vue` is two dialogs in one file

691 lines, the largest component in the repo. About 30 of its symbols are
`tf`-prefixed — `tfGateway`, `tfSelected`, `tfExpanded`, `tfGroups`,
`tfToggleGroup`, `onDiscoverTrueFoundry`, `onConfigureTrueFoundry` … The manual
prefix is the tell: it is namespacing-by-convention inside a shared file, which
is what you do when two features share a component that should be two.

The generic integrations list (connect/OAuth/API key) and the TrueFoundry
discovery flow (gateway probe over PTY, model tree with group selection, config
write) have no state in common. TrueFoundry already owns a store section
(`providers.js`), a lib (`lib/truefoundry.js`) and a doc (`docs/truefoundry.md`);
the UI is the only layer where it is still fused to something else.

**Fixed.** Extracted to `components/dialogs/TrueFoundryCard.vue`, mounted as one
tag in the "Add" tab. `ProvidersDialog.vue` drops **691 → 215 lines** and no
longer imports `lib/truefoundry.js`, `lib/fuzzy.js`, `lib/storage.js`,
`opencodeStore` or six of the store's exports — none of which the integrations
list ever needed. Verified mechanical: the CSS selector set, the `tf*` symbol set
and the `class="tf-…"` node counts are identical before and after.

## C. Exported-but-internal surface

Twenty symbols are exported and never imported anywhere, tests included:

- Used only inside their own module, so the `export` is noise:
  `subagents.js` (`parseAgentFile`, `serializeAgentFile`, `rosterEntry`,
  `writeDirFor`), `drafts.js` (`loadDraft`, `flushDraft`), `theme.js`
  (`THINKING_SIZE_MIN`/`MAX`), `layout.js` (`NARROW_PX` — though this one is
  worth keeping exported as the documented twin of the `responsive.css`
  breakpoint).
- Genuinely unreferenced: `api.js#postJSON`, `confirm.js#alertDialog`,
  `fork.js#forkPromptText`, `git.js#gitStateFor`, `handover.js#extractDocument`
  and `#handoverSeedText`, `projects.js#parentSessionId` and `#isSubagentSession`,
  `providers.js#gatewayURL`, `filesearch.js#fileSearchStore`,
  `models.js#modelInfo`.

Low stakes individually. It matters because an exported symbol reads as a
supported seam — the next person extending `handover.js` will assume
`handoverSeedText` is load-bearing and preserve its shape.

**Fixed, with two deliberate exceptions.** Thirteen symbols lost their `export`
(they are used only inside their own module) and two thin wrappers with no caller
at all — `git.js#gitStateFor`, `projects.js#isSubagentSession` — were deleted.

Kept, on inspection:

- **`confirm.js#alertDialog`** is not dead. `ConfirmDialog.vue` implements the
  alert variant (`kind === "alert"` hides the cancel button), and this is the
  only entry point to it — deleting the function would orphan working UI.
- **`api.js#postJSON`** is the documented half of the `getJSON`/`postJSON` pair
  the module header describes. Removing one side makes the surface less
  predictable than leaving it.
- **`layout.js#NARROW_PX`** stays exported as the documented twin of the
  `responsive.css` breakpoint.

## D. Smaller things

- **`.connect-backdrop` was the app-wide modal backdrop** defined in a partial
  named after one dialog — and it turned out worse than "badly named". Auditing
  each class showed `ConnectDialog.vue` had moved to `<style scoped>` with its
  own `.connect-screen`/`.connect-card` and **uses none of them**: of the 25
  selectors in `connect-dialog.css`, 7 were the shared chrome (8–11 components
  each) and **16 were used by nobody** — dead rules left behind by that move.
  **Fixed:** the shared 7 are now `styles/modal.css`, imported at exactly the
  position `connect-dialog.css` held so the cascade is unchanged; the 16 are
  deleted, which is most of the 1.7 kB the stylesheet lost. `confirm-dialog.css`
  no longer has to explain that it borrows from "the dialog above".
- **`MCP_SERVERS = ["serena"]` hardcoded in `MessageView.vue`.** Same class as
  the customer gateway that finding 10 removed: one deployment's config compiled
  into a view. **Fixed:** `stores/mcp.js` reads the list from `GET /mcp` — a
  route the app already had, used on demand by `McpDialog` — at boot and on every
  stream reconnect, since config is read at server startup. Failure and a 404
  both resolve to an empty list without an error, because this only decides how a
  tool call is labelled. Longest-prefix matching, so a server named `git` can't
  shadow `git_remote`. The mock serves the route.
- **Dependencies.** Was 3 advisories (2 moderate, 1 high); `postcss` is fixed by
  the non-breaking `npm audit fix`. **The remaining 2 are left deliberately**:
  both are vite-dev-server-only (esbuild request forwarding, path traversal in
  optimized-deps `.map` handling, `server.fs.deny` bypass on Windows) and clear
  only by going vite 5 → 8. That is a breaking major under a `vite.config.js`
  whose dynamic `/api/<port>/…` proxy is load-bearing, so it wants its own change
  and its own verification, not a drive-by. Nothing here ships to production —
  `vite build` output has no server. `vue` and `@playwright/test` are one patch
  behind.
- **`pi-frontend-changes.patch`** — a 93KB, 2007-line, already-applied diff
  committed at `d33d3b5`. It no longer applies. Deleted in this pass.
- **`.gitignore` still ignored `server/target/`**, from the Rust server removed
  in the V2 pivot. Removed in this pass.
- **Doc drift**: `localCommands.js`, `codeCopy.js`, `dotenv.js`,
  `placeholders.js`, `thinkingPhrases.js` were absent from the `CLAUDE.md`
  tables, and the testing section still described a suite of nine specs centred
  on the composables — it is now ten specs / ~67 tests spanning transcript,
  permission, providers, usage, handover and dotenv. Both corrected in this pass.

## What's left

A–D are done. Two things were deliberately not taken, and both are decisions
rather than oversights:

- **vite 5 → 8** for the last two advisories (see above): a breaking major under
  a load-bearing proxy config, worth its own change.
- **Running the suite.** `test/escape.spec.js` is new and the rest are untouched,
  but `AGENTS.md` says not to run Playwright unasked, so nothing here has been
  executed against a browser. `npm run build` is clean and the extraction in **B**
  was verified by diffing selector, symbol and node sets rather than by eye.

The next thing worth a pass, not attempted here: `QuestionDialog`, the sidebar
and the sub-agent dialogs still have no spec coverage.

## Is it still composable?

Yes, and by a wider margin than the file sizes suggest. The layering, the facade,
the event table and the run-settling design are all doing real work, and all four
survived a feature drop without being worked around — the July fixes went in at
the layer that owned the problem, which is the actual test of whether a structure
is holding.

The one pattern to watch is the one in finding A: this codebase is good at
introducing the right abstraction and less good at finishing the migration to it.
`useDialogEscape` at 7-of-12 and `<style scoped>` at 20-of-33 were the same shape.
The scoped-styles migration is benign — the two mechanisms compose, and the old
one still works. The Escape migration was not, because the two mechanisms were
*unaware* of each other, and the cost of the gap landed in a third file that
hardcoded a list of the first two's DOM.

Both halves of that finding are worth generalising, because the same thing shows
up twice in this pass. The dead CSS in **D** was a *completed* migration nobody
swept up after: `ConnectDialog` moved to scoped styles and left 16 unused rules
plus a filename that misdescribed what the file had become. The Escape gap was an
*incomplete* one. So: when a migration finishes, delete what it replaced; when it
doesn't finish, the half-state is the expensive part — a partially-adopted
abstraction is worse than none, because the compensating code accumulates in
files that have nothing to do with it.
